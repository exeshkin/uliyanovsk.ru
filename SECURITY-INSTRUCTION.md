# 🔒 Инструкция по безопасности

## 🚨 СРОЧНО: Действия после обнаружения утечки пароля

### Шаг 1: Смените пароль от Yandex (ПРЯМО СЕЙЧАС!)

**Вариант A: Смена основного пароля**
1. Откройте https://passport.yandex.ru/profile
2. Нажмите "Изменить пароль"
3. Придумайте новый надёжный пароль (минимум 12 символов, буквы + цифры)
4. Сохраните

**Вариант B (РЕКОМЕНДУЕТСЯ): Пароль приложения**
1. Откройте https://passport.yandex.ru/profile/access
2. Включите двухфакторную аутентификацию (если ещё не включена)
3. Перейдите в "Пароли приложений" → "Создать новый пароль"
4. Назовите его "SMTP для сайта uliyanovsk.ru"
5. Скопируйте сгенерированный пароль (вида `abcd-efgh-ijkl-mnop`)
6. Используйте этот пароль вместо основного в настройках SMTP

---

### Шаг 2: Создайте файл .env для локальной разработки

**В корне сайта (`uliyanovsk.ru/.env`):**

```env
SMTP_HOST=smtp.yandex.ru
SMTP_PORT=587
SMTP_SECURE=tls
SMTP_USERNAME=anir.u@yandex.ru
SMTP_PASSWORD=ваш_новый_пароль_или_пароль_приложения
MAIL_FROM=anir.u@yandex.ru
MAIL_FROM_NAME="Сайт Общение Христиан"
MAIL_TO=anir.u@yandex.ru
SECRET_KEY=BIGSecret
```

**⚠️ Важно:**
- Файл `.env` **НЕ ДОЛЖЕН** коммититься в Git
- Он уже добавлен в `.gitignore`
- Для каждого разработчика — свой `.env`

---

### Шаг 3: Обновите sendmail.php на сервере

**Вариант A: Использовать новый безопасный файл**
1. Переименуйте `sendmail-safe.php` → `sendmail.php` на сервере
2. Загрузите `.env` файл на сервер в папку `uliyanovsk.ru/`
3. Проверьте работу формы

**Вариант B: Вручную изменить существующий sendmail.php**
Замените строки с паролем на чтение из переменных окружения:

```php
// Было (НЕБЕЗОПАСНО):
$mail->Password = 'hdycbahktagdqywd';

// Стало (БЕЗОПАСНО):
$mail->Password = getenv('SMTP_PASSWORD');
```

---

### Шаг 4: Удалите старый sendmail.php из Git-истории

**⚠️ Внимание:** Пароль всё ещё виден в истории коммитов на GitHub!

Для полного удаления из истории:

```bash
# Локально в проекте:
git filter-branch --force --index-filter \
  'git rm --cached --ignore-unmatch uliyanovsk.ru/sendmail.php' \
  --prune-empty --tag-name-filter cat -- --all

git push origin --force --all
```

**ИЛИ (проще):**
1. Смените пароль (Шаг 1) — это самое важное!
2. Старый файл в истории уже не опасен, если пароль изменён

---

### Шаг 5: Проверьте .gitignore

Убедитесь, что следующие файлы **НЕ** коммитятся:

```
.env
*.env
.env.local
uliyanovsk.ru/data/*.json  (если содержит чувствительные данные)
galaxy.uliyanovsk.ru/data/config.json
galaxy.uliyanovsk.ru/.env
```

## 🔐 Безопасная архитектура

### Что где хранить:

| Тип данных | Где хранить | Коммитить в Git? |
|------------|-------------|------------------|
| Пароли SMTP | `.env` (локально), переменные окружения (сервер) | ❌ НЕТ |
| SESSION_SECRET | `.env` (локально), переменные окружения (сервер) | ❌ НЕТ |
| Пароль админки | Хэш в `data/config.json` (не коммитить) | ❌ НЕТ |
| Контент сайта (JSON) | `data/*.json` | ⚠️ По усмотрению |
| HTML/CSS/JS | Основной код | ✅ ДА |
| Конфиги сервера | `nginx.conf` | ✅ ДА (без паролей) |

## 🛡 Дополнительные рекомендации

### 1. Двухфакторная аутентификация
Включите 2FA для Yandex ID:
- https://passport.yandex.ru/profile/access

### 2. Регулярная смена паролей
- Меняйте пароль приложения каждые 3-6 месяцев
- Обновляйте `.env` после смены

### 3. Мониторинг активности
Проверяйте историю входов:
- https://passport.yandex.ru/profile/activity

### 4. Ограничение доступа к админке
- Используйте IP- whitelist в nginx
- Добавьте basic auth поверх формы входа

### 5. HTTPS обязателен
- Убедитесь, что сайт работает только по HTTPS
- Настройте редирект HTTP → HTTPS (уже есть в nginx.conf)

## 📞 Если что-то пошло нешло

1. **Пароль утек, но вы не можете его сменить:**
   - Восстановите доступ через службу поддержки Yandex
   - https://passport.yandex.ru/restoration

2. **Форма не работает после обновления:**
   - Проверьте, что `.env` файл существует
   - Проверьте права доступа к `.env` (chmod 600)
   - Включите отображение ошибок PHP для отладки

3. **Git история содержит секреты:**
   - Смените все пароли, которые были в истории
   - Используйте `git filter-branch` для очистки истории
   - Или создайте новый репозиторий с чистой историей
